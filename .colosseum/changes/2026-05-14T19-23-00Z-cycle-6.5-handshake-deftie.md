## Motivation

Cycle 6.4 established the def-tying pattern on the simplest single-bundle lift (`verifyGroth16_yields_decoded_negl`). Cycle 6.5 replicates the pattern on `handshake_sound_negl` — and in doing so surfaces a related defect: the lift was over-bundled relative to the classical proof's actual axiom consumption.

## Round-A-adjacent finding: over-bundling correction

The classical `handshake_sound` at `Handshake.lean:64-71` consumes only `verifyGroth16_sound` in its proof (witness quote is `inputs_to_quote h.inputs`; `mrEnclaveOf`/`userDataOf` equalities come directly from `Accepted h`; `tdxVerifier.sound` is not consumed). The Step 6.1 dual-bundle decomposition was over-bundled — the TDX summand was not load-bearing for this particular lift.

Cycle 6.5 corrects this by lifting `handshake_sound_negl` as a single-bundle Groth16-only reduction. The `TdxVerifierSoundAdvantage` Type-alias remains at the module level for downstream lifts (`handshake_binds_ecies_key_negl` etc.) that DO consume TDX-soundness, but is no longer threaded through this lift's hypotheses.

Round A did not name this defect specifically, but it is the same general pattern as attack #4 (cosmetic decomposition): the prior dual-bundle satisfied the *shape* of "two cryptographic primitives are jointly load-bearing" without the *content* — only one was actually used in the supporting classical proof.

## Changes

### Added — content-bearing predicates, reductions, and advantage

In `ProtocolVCVioDual.lean`, after the `handshakeSoundnessGame` def and before the lift theorem:

```lean
def handshakeSoundnessWinPred (h : HandshakeCheck) : Prop :=
  Accepted h ∧
  ¬ ∃ q : TdxQuote,
    was_signed_by_dstack q ∧
    mrEnclaveOf q = some h.expectedMr ∧
    userDataOf q  = some h.msgUserData

def reduce_handshake_to_groth (𝒜 : HandshakeSoundAdv) : Groth16SoundAdv :=
  fun n => do let h ← 𝒜 n; pure (h.proof, h.inputs)

noncomputable def handshakeFailAdv (𝒜 : HandshakeSoundAdv) (n : ℕ) : ℝ≥0∞ :=
  Pr[ handshakeSoundnessWinPred | 𝒜 n ]

theorem handshakeSoundnessWinPred_imp_groth16SoundnessWinPred_projected
    (h : HandshakeCheck) (hp : handshakeSoundnessWinPred h) :
    groth16SoundnessWinPred (h.proof, h.inputs) := by
  obtain ⟨⟨hZk, hMr, hUd⟩, h_neg⟩ := hp
  refine ⟨hZk, ?_⟩
  intro h_signed
  apply h_neg
  exact ⟨inputs_to_quote h.inputs, h_signed, hMr, hUd⟩
```

`groth16SoundnessAdv` and `groth16SoundnessWinPred` are imported from cycle 6.4's `ProtocolVCVio` module (already opened in this file).

### Replaced — the lift theorem itself

Was (9 params, including free `handshakeFailAdv`, two free advantage abbrevs, and assumed `h_bound`):
```lean
theorem handshake_sound_negl
    (𝒜 : HandshakeSoundAdv)
    (𝒜_groth : Groth16SoundAdv)
    (𝒜_tdx : TdxVerifierSoundAdv)
    (handshakeFailAdv : HandshakeSoundAdv → ℕ → ℝ≥0∞)
    (groth16Adv : Groth16SoundAdvantage)
    (tdxAdv : TdxVerifierSoundAdvantage)
    (h_bound : ∀ n, handshakeFailAdv 𝒜 n ≤ groth16Adv 𝒜_groth n + tdxAdv 𝒜_tdx n)
    (h_groth_negl : negligible (groth16Adv 𝒜_groth))
    (h_tdx_negl : negligible (tdxAdv 𝒜_tdx)) :
    negligible (handshakeFailAdv 𝒜) :=
  negligible_of_le h_bound (negligible_add h_groth_negl h_tdx_negl)
```

Now (2 params; bound is proven; bundle is single-Groth16):
```lean
theorem handshake_sound_negl
    (𝒜 : HandshakeSoundAdv)
    (h_groth_negl :
      negligible (groth16SoundnessAdv (reduce_handshake_to_groth 𝒜))) :
    negligible (handshakeFailAdv 𝒜) := by
  refine negligible_of_le ?_ h_groth_negl
  intro n
  show Pr[ handshakeSoundnessWinPred | 𝒜 n ] ≤
       Pr[ groth16SoundnessWinPred | reduce_handshake_to_groth 𝒜 n ]
  rw [show reduce_handshake_to_groth 𝒜 n
        = 𝒜 n >>= pure ∘ (fun h : HandshakeCheck => (h.proof, h.inputs))
        from rfl,
      probEvent_bind_pure_comp]
  exact probEvent_mono (fun h _ hp =>
    handshakeSoundnessWinPred_imp_groth16SoundnessWinPred_projected h hp)
```

The proof's key new tactic is `probEvent_bind_pure_comp`, which rewrites `Pr[q | mx >>= pure ∘ f]` to `Pr[q ∘ f | mx]` — exactly the move needed to relate the reduced-adversary's win probability to the original-adversary's projected win probability.

## What Round A attacks this addresses (for this lift only)

- **Attack #1 (Triviality / free-symbol tautology)**: closed. `handshakeFailAdv` is a `def` over `Pr[…]`. The user cannot instantiate it to `0`.
- **Attack #2 (Trojan-horse `h_bound`)**: closed. `h_bound` is gone; the bound is proven internally via `probEvent_mono` + `probEvent_bind_pure_comp`.
- **Attack #3 (no reduction at terminal lift)**: closed for this lift's level. `reduce_handshake_to_groth` is a concrete `def`, not a free parameter. The bundle adversary IS derived from the main adversary by a named function.
- **Attack #11 (over-quantified signature)**: closed. The lift takes one adversary and one hypothesis; no dangling probability-valued parameters.

## Axiom closure verification

```

   Specs.Quartz.Attestation.Zkdcap.groth16Verifier]
```

`tdxVerifier` is in the closure because `mrEnclaveOf` / `userDataOf` (used in `handshakeSoundnessWinPred`) are projections derived from `tdxVerifier.verify`. The `.sound` and `.complete` *projections* are NOT separately consumed — neither `verifyTdxQuote_sound` nor `verifyTdxQuote_complete` appears in the proof. `groth16Verifier` is in the closure as the substrate of `verifyGroth16`/`zkdcapVKey`, with `groth16Verifier.sound` shadowed by `h_groth_negl`.

This matches the Round A-reframed closure invariant: the lift's closure contains the verifier *records* (because they define the substrate the security claim is over) but not their soundness *projections* (because those are shadowed by the parametric negligibility hypothesis).

## Downstream impact

`handshake_sound_negl` and `handshakeFailAdv` are referenced in only one place outside this file (a docstring at `ProtocolVCVioTriple.lean:131`). No downstream theorem currently consumes `handshake_sound_negl` as a building block. Triple/Quad lifts re-derive their own handshake-style predicates inline. The single-bundle correction therefore has zero downstream-breakage cost.

`handshakeFail_secure_of_dual_bundle_secure` and `handshakeSoundnessGame_secure_of_dual_bundle_secure` (the `SecurityExp` / `SecurityGame` packagings, dual-bundle in shape) remain unchanged. They are generic over arbitrary `SecurityExp` / `SecurityGame` summand decompositions — a caller who wants to bound `handshakeFailExp.advantage` by a sum of two terms can still do so, the second summand being optionally zero.
