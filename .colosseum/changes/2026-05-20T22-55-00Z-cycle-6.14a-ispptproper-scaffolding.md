## What this cycle adds

Two pieces of scaffolding for the future `_AGAINST_PPT_ADVERSARIES`
packagings:

1. **Four `Classical.decEq` local instances** for the abstract
   carrier types underlying `ProtocolSpec`'s index:
   `UserDataCommit`, `ByteSeq`, `TdxQuote`, `VerifyGroth16Query`.
   Required by `PolyQueries`'s `[DecidableEq ι]` parameter.
   `noncomputable local`, matching the
   `Classical.propDecidable` precedent already used for
   `was_signed_by_dstack` decidability.

2. **`noncomputable def IsPPT_proper`** polymorphic in the
   adversary's result type `T`:

   ```lean
   noncomputable def IsPPT_proper {T : Type}
       (𝒜 : ℕ → OracleComp ProtocolSpec T) : Prop :=
     Nonempty (PolyQueries
       (ι := (((UserDataCommit ⊕ ByteSeq) ⊕ TdxQuote) ⊕ VerifyGroth16Query))
       (spec := fun _ : ℕ => ProtocolSpec)
       (α := fun _ : ℕ => PUnit) (β := fun _ : ℕ => T)
       (fun n (_ : PUnit) => 𝒜 n))
   ```

   `PUnit` adapts our adversaries' `ℕ → OracleComp ...` shape into
   PolyQueries's expected `(n : ℕ) → α n → OracleComp (spec n) (β n)`.
   `Nonempty` is the standard `Prop` shape for "there exists a
   PolyQueries witness".

## Why a parallel predicate, not a body swap of `IsPPT`

Replacing `IsPPT := True` with the PolyQueries body would weaken
the conclusion of every existing `*_AGAINST_UNBOUNDED_ADVERSARIES`
packaging from "secure against all adversaries" to "secure against
PPT adversaries only". The packagings' naming would no longer
match their conclusion.

Keeping the placeholder `IsPPT` as the "all-adversaries" label
(honest under the cycle-6.12 rename) and introducing
`IsPPT_proper` separately preserves backwards compatibility while
unblocking the substantive PPT statement. A parallel set of
`_AGAINST_PPT_ADVERSARIES` packagings consuming `IsPPT_proper` is
queued as cycle 6.15.

## Honesty caveat on `Classical.decEq`

The four `Classical.decEq` instances assert decidable equality on
abstract carriers under classical logic. The instances are
`noncomputable local` to prevent leak into downstream type-class
search (mirroring the `Ecies.DecidableEq PubKey` and
`was_signed_by_dstack` patterns).

The instances add `Classical.choice` to the closure of any theorem
that uses them. They do not claim the underlying equality is
computationally decidable — only that the proposition `a = b` is
syntactically `Decidable` so that `PolyQueries`'s `[DecidableEq ι]`
constraint is satisfied.

When concrete carrier refinement lands (the queued
`DomainSep`/`Addr`/`PubKey`/etc. → `BitVec n` / byte-list
substitution), these instances will be replaced by computable
ones; no theorem statement needs to change.
