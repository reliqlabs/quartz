## What this cycle adds

### Cycle 6.14.b: preservation lemmas

A generic `IsPPT_proper_of_bind_pure_comp` in `ProtocolVCVio.lean`:

```lean
theorem IsPPT_proper_of_bind_pure_comp {S T : Type}
    (𝒜 : ℕ → OracleComp ProtocolSpec S) (f : S → T)
    (h : IsPPT_proper 𝒜) :
    IsPPT_proper (fun n => 𝒜 n >>= pure ∘ f) := by
  obtain ⟨⟨qb, hqb⟩⟩ := h
  refine ⟨⟨qb, ?_⟩⟩
  intro n _
  show IsPerIndexQueryBound (𝒜 n >>= pure ∘ f) _
  rw [← map_eq_bind_pure_comp, isPerIndexQueryBound_map_iff]
  exact hqb n PUnit.unit
```

The proof is two lines (a `show` to beta-reduce the lambda, then a
rewrite chain via `← map_eq_bind_pure_comp` + `isPerIndexQueryBound_map_iff`)
because VCV-io's `isPerIndexQueryBound_map_iff` already states that
post-composing with a pure map preserves the per-index query bound.

Five per-reduction corollaries discharge `IsPPT_proper` of each
specific reduction via the generic lemma:

| Module | Corollary |
|---|---|
| `ProtocolVCVioDual.lean` | `reduce_handshake_to_groth_preserves_IsPPT_proper` |
| `ProtocolVCVioTriple.lean` | `reduce_binds_to_groth_preserves_IsPPT_proper` |
| `ProtocolVCVioTriple.lean` | `reduce_transfers_to_groth_preserves_IsPPT_proper` |
| `ProtocolVCVioTriple.lean` | `reduce_auctionDeterm_to_groth_preserves_IsPPT_proper` |
| `ProtocolVCVioQuad.lean` | `reduce_crossSessionBind_to_groth_preserves_IsPPT_proper` |

Each is a one-line invocation of the generic lemma with the
appropriate projection function. The generic lemma's existence
means all five corollaries are mechanical; future reductions of
the same `bind/pure ∘ f` shape get the same treatment.

Each PPT-variant:

- Replaces `secureAgainst IsPPT` with `secureAgainst IsPPT_proper`
  in both the bundle hypotheses and the conclusion.
- Adds a `reduce_preserves_ppt` hypothesis bundling the
  preservation claim for the reduction's output tuple
  (3-conjunction for triple-bundle, 5-conjunction for the
  quadruple).
- Replaces `IsPPT_trivial _` discharges with
  `(reduce_preserves_ppt A hA).N` projections.

The proof shapes are otherwise identical to the UNBOUNDED variants.

## What this cycle does NOT do

The PPT-bounded packagings are generic over `reduce`; they do not
hardwire the proven reductions (`reduce_handshake_to_groth`, etc.).
Callers who use the proven reductions can discharge the
`reduce_preserves_ppt` premise via the cycle-6.14.b corollaries
(with some pair-vs-single coercion when the actual reduction is
single-bundle but the packaging is multi-bundle).

A potential cycle 6.14.d would add wrapper theorems specialised to
each proven reduction, dropping the `reduce_preserves_ppt` premise
entirely. Not landed here — the current shape is sufficient for
downstream callers to wire up, and any pair-coercion choice is
caller-specific.
