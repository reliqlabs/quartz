## What landed

Two theorems proved from VCV-io's `probEvent_logCollision_le_birthday_total`:

```lean
theorem commitHash_logCollision_birthday_bound {α : Type}
    (oa : OracleComp CommitHashSpec α)
    (n : ℕ) (hbound : IsTotalQueryBound oa n) :
    Pr[fun z => LogHasCollision z.2 |
        (simulateQ loggingOracle oa).run] ≤
      (n ^ 2 : ℝ≥0∞) / (2 * 2 ^ 512)

theorem commitHashBytes_logCollision_birthday_bound {α : Type}
    (oa : OracleComp CommitHashBytesSpec α)
    (n : ℕ) (hbound : IsTotalQueryBound oa n) :
    Pr[fun z => LogHasCollision z.2 |
        (simulateQ loggingOracle oa).run] ≤
      (n ^ 2 : ℝ≥0∞) / (2 * 2 ^ 512)
```

Axiom closure for both: `{propext, Classical.choice, Quot.sound}` only.
No protocol-layer or cryptographic axioms; the textbook birthday bound
is proved from first principles via VCV-io's library theorem.

## Retraction of the cycle-6.22.a blocker note

The cycle-6.22.a change record claimed:

> VCV-io's `probEvent_logCollision_le_birthday_total` requires
> `OracleSpec.Fintype spec` which extends `PFunctor.Fintype` requiring
> `Fintype` on BOTH the *index* type and the *range* type.

That reading was wrong. Re-checking
`VCVio/ToMathlib/PFunctor/Basic.lean:231`:

```lean
protected class Fintype (P : PFunctor.{uA, uB}) where
  fintype_B : ∀ a, Fintype (P.B a)
```

`PFunctor.Fintype` requires Fintype on each *branch* (`P.B a`), which
for an `OracleSpec` maps to `Range t`. The *index* type (`P.A` / spec
domain) only needs `DecidableEq`, supplied separately.

The actual typeclass prerequisites at
`VCVio/OracleComp/QueryTracking/Birthday.lean:20-21,397`:

* `[DecidableEq ι]` on index — `Classical.decEq UserDataCommit` ✓
* `[spec.DecidableEq]` — derives from above + DecidableEq (BitVec 512) ✓
* `[spec.Fintype]` — derives from Fintype (BitVec 512) ✓
* `[spec.Inhabited]` — derives from Inhabited (BitVec 512) ✓
* `[Inhabited ι]` — supplied as concrete default UserDataCommit ✓

All satisfiable directly over the cycle-6.21 refinement. The bound
theorem statement is well-typed over `CommitHashSpec` as-is; no
bounded-variant spec, no upstream PR, no cycle-6.21 revert needed.

## Methodology meta-finding

The original blocker note was based on a single read of `OracleSpec.Fintype`
that conflated `P.A` (index) and `P.B` (branches). A 5-minute re-check
of the actual definition would have caught it. This is the second
instance in the cycle-6.22 sequence where a claimed "out-of-session
blocker" dissolved on closer reading (the first was the cycle-6.14.a
`DecidableEq UserDataCommit` instance, claimed initially as a scoping
issue and resolved by moving the RO scaffolding to a new module). Both
were structural-level claims about VCV-io's API rather than substantive
proof obligations.

Add to colosseum methodology v0.4 ask candidates: **for any
"insurmountable blocker" claim against an upstream library API, require
a direct quote of the API's actual signature in the change record
before closing the cycle.** The cost is 5 minutes of API-source reading;
the benefit is catching cases where the blocker is a misreading rather
than a real incompatibility.
