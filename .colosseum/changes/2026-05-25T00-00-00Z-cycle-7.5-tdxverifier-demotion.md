## What landed

The bundled `axiom tdxVerifier (n : Nat) : TdxVerifier n` is gone. In its place:

```lean
noncomputable def tdxVerifier (n : Nat) : TdxVerifier n :=
  dcapTdxVerifier n productionCollateral productionCollateral_fresh
```

The verifier is now constructed by instantiating the cycle-7.x reference DCAP verifier `dcapTdxVerifier` (which composes `parseDcapQuote`, `verifyX509Chain`, `verifyEcdsaP256`, `verifyAttestationKeyBinding`, `qeReportBytes`, `composeMrEnclave`, `projectUserData`, `checkTcbLevel`, `checkQeIdentity`) at the deployment-side production collateral bundle.

* **`Specs/Quartz/Attestation/Dstack.lean`** (rewrite): now imports both `DstackCarriers` and `DcapVerifier`. Defines `tdxVerifier` as derived (above). The five derived projections (`verifyTdxQuote`, `verifyTdxQuote_sound`, `verifyTdxQuote_complete`, `userDataOf`, `mrEnclaveOf`) and `projections_some_of_verify` are unchanged in shape but inherit the new closure.

No downstream consumer file (`Zkdcap.lean`, `Protocol/*.lean`, `Crypto/*.lean`) required any edit. The namespace `Specs.Quartz.Attestation.Dstack` is shared between `DstackCarriers.lean` and `Dstack.lean`, so consumers' `open Specs.Quartz.Attestation.Dstack` resolves names from both files transparently.

## Why `axiom` not `opaque` for `productionCollateral` and `productionCollateral_fresh`

Initial attempt used `opaque productionCollateral : Collateral` and `opaque productionCollateral_fresh : freshCollateral productionCollateral`. Lean required `Inhabited`/`Nonempty` instances for both, which `Collateral` (a deeply nested structure with `BitVec n` fields) does not derive automatically and `freshCollateral` (a `Prop`) cannot.

Switched to `axiom` for both. The audit consequence is intentional: they now appear in `#print axioms` of every downstream theorem, making the deployment-side value-witnesses **visible in the axiom closure** rather than hidden behind opaque-definitional irreducibility. The honest read is "the in-fork proof relies on Intel's collateral being fetched and rotated within the next-update window" — exactly the right deployment-side obligation to surface.

## Methodology meta-finding

Two observations from this cycle for the colosseum methodology v0.4 candidates:

1. **File-dependency-cycle resolution by carrier extraction**: when an in-fork refactor needs file A to depend on file B which already depends on A, extract the shared surface (carrier types + minimal axioms) into a third file C, and have both A and B import C. Done correctly, no downstream consumer needs to know about the split (namespace can be shared). This pattern is reusable for similar in-Lean dependency-cycle situations across other verification fork projects.
2. **`axiom` vs `opaque` for `Prop`-valued value-witnesses**: `opaque p : Prop` requires Nonempty (which `Prop`s can't always give); `axiom p : Prop` doesn't. For deployment-side value-witnesses (e.g. `productionCollateral_fresh`) the `axiom` form is *also* the more audit-honest choice because it surfaces the witness in `#print axioms` closures — exactly what an audit wants to see.
