## Context — what the cycle-7.7 adversarial review found

After cycle 7.5 (`axiom tdxVerifier` demotion) and cycle 7.6 (single `signedRegion` linkage axiom) landed, `colosseum-spec-adversary` returned a fresh review with 4 critical, 4 high, 3 medium, 2 low findings:

* **C1**: cycle 7.6 axiom is dead weight — used by one corollary nothing downstream cites.
* **C2**: cycle 7.6 pins only `signedRegion`; an adversarial parser still controls every other output field (mrTd, reportData, attestationKey, qeReport, certificateData), which break measurement binding silently.
* **C3**: `dcapVerifier_sound`'s conclusion `was_signed_by_dstack q` doesn't bind the returned `(mr, ud)` to `q` — the rename to derived definition gave reviewers the false impression that binding is machine-checked.
* **C4**: `productionCollateral_fresh` is a perpetual freshness oracle (no temporal index).
* **H1**: cycle 7.5 is a relabeling, not a net axiom reduction. Total trust surface went UP, not down.
* **H2**: `verified_chain_implies_dstack_signed` is a load-bearing axiom encoding the entire verifier algorithm.
* **H3**: `dcapVerifier_complete` is over-strong (binds completeness to any fresh collateral, not the specific one the chain anchors to).
* **H4**: `freshCollateral` is still structurally undefined.
* **M1**: `axiom` vs `opaque` framing for value-witnesses was theater, not a real audit improvement.
* **M2**: namespace reuse for `DstackCarriers.lean` hides the layering invariant.
* **M3**: `composeMrEnclave := body.mrTd` drops RTMRs silently.
* **L1**: cycle 7.6 docstring overclaims load-bearingness.
* **L2**: `projectUserData`'s `n ≠ 512` branch is a silent footgun.

## What landed in cycle 7.7

Address findings C2 + C3 (the highest-impact pair — they together explain why cycle 7.6 was insufficient to close the parser-decoupling attack):

### New definitions in `DcapVerifier.lean`

```lean
opaque extractBitVec (raw : RawBytes) (offset width : Nat) : BitVec width

axiom parseDcapQuote_mrTd_eq (raw : RawBytes) (q : DcapQuote) :
    parseDcapQuote raw = some q →
    q.body.mrTd = extractBitVec raw 64 384

axiom parseDcapQuote_reportData_eq (raw : RawBytes) (q : DcapQuote) :
    parseDcapQuote raw = some q →
    q.body.reportData = extractBitVec raw 568 512

theorem verifyDcap_output_bound_to_input
    (n : Nat) (raw : RawBytes) (col : Collateral)
    (mr : MrEnclave) (ud : UserData n) :
    verifyDcap n raw col = some (mr, ud) →
    mr = extractBitVec raw 64 384 ∧
    (if h : n = 512 then ud = h ▸ extractBitVec raw 568 512
     else ud = BitVec.ofNat n (extractBitVec raw 568 512).toNat)
```

### Closure verification

* `verifyDcap_output_bound_to_input` closure: `{propext, parseDcapQuote_mrTd_eq, parseDcapQuote_reportData_eq}` — both field axioms load-bearing.

Retracted in this cycle's ledger update (below).

* **L1** (cycle 7.6 docstring overclaim): retracted in this cycle's edits to the cycle-7.6 axiom docstring.
* **L2** (`projectUserData` truncation footgun for `n < 512`): minor; would benefit from `(h : n ≥ 512)` precondition on `dcapTdxVerifier` but cascades.

## Methodology meta-finding

The cycle-7.6 mistake was a useful diagnostic: adding a single field-binding axiom does NOT close the parser-decoupling attack surface; the audit transparency only improves when ALL output-flowing fields are pinned. Future axiom-by-axiom refactors should first enumerate the output-flowing field set, then write the axioms together, rather than picking one field at a time. The cycle-7.7 review's finding C2 made this pattern explicit; promote to colosseum methodology v0.4 candidate as **field-binding axioms must close the full output surface, not a single representative field**.
