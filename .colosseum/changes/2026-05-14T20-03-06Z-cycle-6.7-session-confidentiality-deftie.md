## Motivation

Cycles 6.4–6.6 established the def-tying pattern for lifts whose classical proof had at least one surviving probabilistic-failure mode (Groth16-soundness). Cycle 6.7 extends the pattern to a lift whose classical proof has **no surviving probabilistic-failure mode** under the current spec abstraction.

## Round-A-adjacent finding: failure event is unconditionally impossible

The classical `session_confidentiality` at `Confidentiality.lean:55-66` concludes `decrypt sk (encrypt c.eciesPubkey msg) = some msg`. Its proof uses the third conjunct of `handshake_binds_ecies_key`, which in turn projects from `roundtrip` (an *unconditional theorem* in `Ecies.lean`, not a separately-named axiom). Given the hypothesis `keyOf sk = c.eciesPubkey`, rewriting via `h_sk` reduces the conclusion to `roundtrip sk msg`, which holds unconditionally.

The corresponding failure event in the lift — "hypotheses hold but `decrypt sk (encrypt c.eciesPubkey msg) ≠ some msg`" — is therefore **provably impossible** for every input the adversary could produce. `Pr[failure | 𝒜 n] = 0` for all `𝒜` and `n`.

## What the lift correctly claims, and what it does not

**Correctly claims** (with no parametric hypothesis): the deterministic-roundtrip failure event in the spec's current ECIES abstraction is identically zero.

**Does not claim**: cryptographic IND-CPA security of ECIES. The classical `session_confidentiality` does not model an adversary that observes ciphertexts and tries to distinguish messages; it only models the (unconditional) roundtrip equality. Modelling IND-CPA security would require:

- A CPA-style win event (e.g. `Pr[adversary distinguishes b=0 from b=1 in the ECIES challenge game] - 1/2`).
- An ECIES IND-CPA hypothesis as a parametric negligibility assumption on the spec-level `encrypt` operation.
- A reduction from the protocol-level confidentiality game to the underlying IND-CPA game.

That refactor is its own cycle (cycle 6.X, not in scope for cycle 6.7). The current spec models only the deterministic-roundtrip property, and cycle 6.7 is honest about lifting precisely what the classical proof claims — no more, no less.

## Changes

### Added — content-bearing predicates, advantage, and unconditional-falsity theorem

In `ProtocolVCVioTriple.lean`, between the `session_confidentiality_classical` corollary and the `session_confidentiality_negl` theorem:

```lean
def sessionConfWinPred
    (p : HandshakeCheck × UserDataCommit × PrivKey × Plaintext) : Prop :=
  let (h, c, sk, msg) := p
  Accepted h ∧
  h.msgUserData = commitHash c ∧
  keyOf sk = c.eciesPubkey ∧
  ¬ decrypt sk (encrypt c.eciesPubkey msg) = some msg

theorem sessionConfWinPred_false
    (p : HandshakeCheck × UserDataCommit × PrivKey × Plaintext)
    (hp : sessionConfWinPred p) : False := by
  obtain ⟨_, _, h_sk, h_neg⟩ := hp
  apply h_neg
  rw [← h_sk]
  exact roundtrip p.2.2.1 p.2.2.2

noncomputable def confFailAdv
    (𝒜 : SessionConfidentialityAdv) (n : ℕ) : ℝ≥0∞ :=
  Pr[ sessionConfWinPred | 𝒜 n ]
```

### Replaced — the lift theorem itself

Was (11 free params, including assumed `h_bound` and three independent negligibility hypotheses):

```lean
theorem session_confidentiality_negl
    (𝒜 : SessionConfidentialityAdv)
    (𝒜_groth : Groth16SoundAdv) (𝒜_tdx : TdxVerifierSoundAdv) (𝒜_hash : CommitHashCollisionAdv)
    (confFailAdv : SessionConfidentialityAdv → ℕ → ℝ≥0∞)
    (groth16Adv : Groth16SoundAdvantage) (tdxAdv : TdxVerifierSoundAdvantage)
    (hashAdv : CommitHashCollisionAdvantage)
    (h_bound : ∀ n, confFailAdv 𝒜 n ≤ groth16Adv 𝒜_groth n + tdxAdv 𝒜_tdx n + hashAdv 𝒜_hash n)
    (h_groth_negl ...) (h_tdx_negl ...) (h_hash_negl ...) :
    negligible (confFailAdv 𝒜) := ...
```

Now (one param, no hypotheses):

```lean
theorem session_confidentiality_negl
    (𝒜 : SessionConfidentialityAdv) :
    negligible (confFailAdv 𝒜) := by
  have h_zero : ∀ n, confFailAdv 𝒜 n = 0 := by
    intro n
    refine le_antisymm ?_ (zero_le _)
    calc Pr[ sessionConfWinPred | 𝒜 n ]
        ≤ Pr[ fun _ => False | 𝒜 n ] := by
          exact probEvent_mono (fun p _ hp => sessionConfWinPred_false p hp)
      _ = 0 := probEvent_False _
  have h_fun_zero : confFailAdv 𝒜 = 0 := by funext n; exact h_zero n
  rw [h_fun_zero]
  exact negligible_zero
```

Proof structure: bound `Pr[winPred | 𝒜 n]` from above by `Pr[fun _ => False | 𝒜 n] = 0` via `probEvent_mono` (using the forward implication `winPred → False`) and `probEvent_False`. Then negligibility of `confFailAdv 𝒜 = 0` follows from `negligible_zero`.

## What this addresses

- **Round A attacks #1, #2, #3, #11**: structurally closed (advantage is a `def`, no `h_bound` parameter, no free reduction adversaries, no over-quantified signature).

## What this does NOT address (deferred)

The full IND-CPA security claim for ECIES. The current lift makes the (correct but limited) claim that the spec's deterministic-roundtrip failure event has probability zero; it does not claim anything about chosen-plaintext attacks. A future cycle could refactor `Confidentiality.lean` and `Ecies.lean` to model probabilistic encryption, define a CPA-style game and adversary, and lift `session_confidentiality_negl` to consume an ECIES IND-CPA hypothesis.

## Pattern observation — a new sub-kind in the cycle plan

Cycles 6.4 / 6.5 / 6.6 produced lifts with **one surviving probabilistic-failure mode** (Groth16-soundness in each case). Cycle 6.7 produces a lift with **no surviving probabilistic-failure mode** — the spec models only deterministic facts.

This is a structurally distinct sub-pattern that the original Step 6.0 → 6.3 plan did not anticipate. The plan classified `session_confidentiality_negl` as triple-bundle; the cycle-6.7 analysis shows it is *zero-bundle* under the current spec abstraction. The right framing: the cycle plan should distinguish **content-bearing lifts** (≥ 1 surviving failure mode) from **degenerate lifts** (0 surviving failure modes, advantage = 0).

The latter are honest within the spec but require a separate refactor to make a real cryptographic claim. Worth flagging to the colosseum methodology — when a lift's advantage proves to be identically zero, the cycle should explicitly state whether (a) the spec is intentionally not modelling the relevant probabilistic phenomenon, or (b) the lift is genuinely vacuous and the underlying theorem should not be called a "security lemma."

For session_confidentiality, the answer is (a): the spec models deterministic correctness, not CPA security. The cycle's change record makes this explicit.
