## What Round A attack #8 was about

The triple-bundle lifts (`handshake_binds_ecies_key`,
`session_confidentiality`, etc.) parametrise over a
`CommitHashCollisionAdvantage` (and analogously
`CommitHashBytesCollisionAdvantage`), both of which were defined as
`Type`-only `abbrev`s:

```lean
abbrev CommitHashCollisionAdvantage : Type :=
  CommitHashCollisionAdv → ℕ → ℝ≥0∞
```

Round A flagged this as a content-free framing: the advantage was
not tied to a `Pr[…]` event involving the actual `commitHash`
function, so a caller could instantiate it as `fun _ _ => 0` and
trivialise the conclusion — exactly the same vacuity-by-free-symbol
pattern that cycle 6.4 closed for `Groth16SoundAdvantage`.

## What this cycle adds

Two content-bearing `def`s mirroring the cycle-6.4 pattern:

```lean
def commitHashCollisionWinPred (p : UserDataCommit × UserDataCommit) : Prop :=
  p.1 ≠ p.2 ∧ commitHash p.1 = commitHash p.2

noncomputable def commitHashCollisionAdv
    (𝒜 : CommitHashCollisionAdv) (n : ℕ) : ℝ≥0∞ :=
  Pr[ commitHashCollisionWinPred |
      simulateQ protocolSpecHonestSim (𝒜 n) ]
```

…and the analogous pair for `CommitHashBytes`:

```lean
def commitHashBytesCollisionWinPred (p : ByteSeq × ByteSeq) : Prop :=
  p.1 ≠ p.2 ∧ commitHashBytes p.1 = commitHashBytes p.2

noncomputable def commitHashBytesCollisionAdv
    (𝒜 : CommitHashBytesCollisionAdv) (n : ℕ) : ℝ≥0∞ :=
  Pr[ commitHashBytesCollisionWinPred |
      simulateQ protocolSpecHonestSim (𝒜 n) ]
```

These are `def`s, not `abbrev`s. The body mentions `commitHash` /
`commitHashBytes` explicitly so an external auditor can read off
exactly which cryptographic event is being bounded. The advantage
is over the adversary's `OracleComp ProtocolSpec` output via
`simulateQ protocolSpecHonestSim`, consistent with cycle 6.13.

## Honesty caveat

The advantage `commitHashCollisionAdv 𝒜 n` is well-typed and
content-bearing, but under the current `commitHashE` axiom (which
is mathematically impossible by pigeonhole), the collision event
`p.1 ≠ p.2 ∧ commitHash p.1 = commitHash p.2` has probability zero
for any adversary — the axiom *asserts* injectivity, so collisions
are propositionally impossible.

This is not a soundness bug in the def-tying; it is a reflection
of the fact that the lift's content depends on whether the
underlying hash axiom is honest. With the current (impossible)
axiom, `commitHashCollisionAdv 𝒜 = 0`, so the negligibility
hypothesis `negligible (commitHashCollisionAdv 𝒜)` is trivially
satisfied — but the carrier-refined replacement (where collisions
are possible with negligible-but-non-zero probability) is what the
def-tying is preparing for.
