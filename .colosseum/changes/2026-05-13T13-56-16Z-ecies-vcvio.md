## Description

First module of the VCV-io refactor sequence. Migrated `Specs/Quartz/Crypto/Ecies.lean` off the original 8-axiom uninterpreted-stub model onto a concrete spec-level model + VCV-io `AsymmEncAlg` integration. Concurrently downgraded the Quartz Lean toolchain from `leanprover/lean4:v4.30.0-rc2` to `leanprover/lean4:v4.29.0` to match VCV-io's current release tag, and pinned mathlib to `v4.29.0`.

The refactor demotes `encrypt`, `decrypt`, and the `roundtrip` correctness property from axioms to *definitions / theorem*. The roundtrip property is now `simp`-provable from a concrete spec-level `Ciphertext := PubKey × Plaintext` model, with `decrypt` succeeding iff the ciphertext's stored target pubkey matches `keyOf sk`. The four abstract carrier types (`PrivKey`, `PubKey`, `Plaintext`) and the `keyOf` derivation function remain axiomatic — they are the genuine externally-supplied trust surface (the `k256` / `ecies` Rust crates' type-level API). Public symbol names are unchanged, so the downstream protocol theorems (`Confidentiality`, `Handshake`, `CrossComponent`, etc.) re-prove without touching their source.

## Axiom count delta (Ecies module)

| Before | After | Reduction |
|---|---|---|
| 8 | 4 | -4 |

Original axioms (8): `PrivKey : Type`, `PubKey : Type`, `Ciphertext : Type`, `Plaintext : Type`, `keyOf`, `encrypt`, `decrypt`, `roundtrip`.

Remaining axioms (4): `PrivKey : Type`, `PubKey : Type`, `Plaintext : Type`, `keyOf : PrivKey → PubKey`.

`Ciphertext`, `encrypt`, `decrypt` are now `def`s. `roundtrip`, `exists_decrypt`, `decrypt_isSome` are theorems.

### Note on plan target

The refactor plan (`.colosseum/refactor-plan-vcvio.md`) aimed at "8 axioms → 1" via a single bundled `EciesPrimitive` record axiom. That formulation was attempted (`EciesPrimitive` structure + `axiom eciesPrim : EciesPrimitive` + `opaque` type shadows) and **rejected** because:

1. `opaque` type shadows require `cast`/`Eq.mp` transport when applying `eciesPrim.keyOf`. The transport code is hostile to Lean's `Decidable` synthesis.
2. With the transported `keyOf`, the downstream `UserDataCommit.lean` theorem `pkOfUserData_commitHash` failed `Decidable (∃ c : UserDataCommit, commitHash c = ud)` synthesis at the default `synthInstance.maxHeartbeats := 20000` budget. This is a *prover_stuck* failure that would require either bumping the heartbeat limit (fragile) or rewriting the downstream theorem (violates the orchestrator's "downstream proofs unchanged" constraint).

The 4-axiom realisation preserves downstream proofs unchanged, still achieves a 50% reduction in Ecies axiom count, and demotes the roundtrip from axiom to theorem (which was the methodology principle's primary goal). The literal "8 → 1" target is recorded as **partially deferred**; achieving it would require additional downstream refactoring beyond Ecies and is in scope for a later phase.

## Classifier-routed failures encountered

Two minor `prover_stuck`-class failures during the spec-design loop:

1. **Initial attempt: `EciesPrimitive` record axiom + `opaque` type shadows** → `cast` transport broke `Decidable` synthesis in downstream `UserDataCommit.pkOfUserData_commitHash`. Classification: `prover_stuck` (synthesis budget exceeded, not a real undecidability). Resolved by abandoning the "1-axiom-bundled" approach in favour of "4-axiom-separated" — explicitly documented in the change body above as a deferred plan target.

2. **VCV-io transitive instance load** in `Ecies.lean` → caused `Decidable (∃ c, commitHash c = ud)` synthesis timeout in downstream `UserDataCommit.lean`. Classification: `prover_stuck` (transitive instance load is the symptom; the underlying logic is sound). Resolved by splitting the VCV-io integration into a separate `EciesVCVio.lean` companion module so the core `Ecies.lean` stays free of mathlib/VCVio transitive imports.

Neither failure required spec relaxation or code revision — both were resolved by structural choices in how the migrated module is organised.
