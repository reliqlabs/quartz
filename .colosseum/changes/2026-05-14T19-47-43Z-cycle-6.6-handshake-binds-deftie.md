## Motivation

Cycle 6.6 is the first **triple-bundle** lift in the plan. The pattern from cycles 6.4 and 6.5 generalises mechanically, but cycle 6.6 also surfaces a second over-bundling case: the prior triple-bundle decomposition was over-bundled relative to the classical proof's actual axiom consumption.

## Round-A-adjacent finding: triple → single-bundle correction

The classical `handshake_binds_ecies_key` proof at `Handshake.lean:90-104` has a three-conjunct conclusion `P1 ∧ P2 ∧ P3`:

- **P1** (`∃ q, was_signed_by_dstack q ∧ userDataOf q = some h.msgUserData`): failure event is a Groth16-soundness break (forward direction). Probabilistic — reduces to `groth16SoundnessAdv` on `(proof, inputs)`.
- **P2** (`pkOfUserData h.msgUserData = some c.eciesPubkey`): unconditionally true in the classical chain via the theorem `pkOfUserData_commitHash`, which derives from `commitHash_inj` (projection of the bundled `commitHashE`). No probabilistic failure event in the current carrier model.
- **P3** (`decrypt sk (encrypt c.eciesPubkey pt) = some pt`): unconditionally true given `keyOf sk = c.eciesPubkey` via the theorem `roundtrip` (derived from how `encrypt`/`decrypt` are defined; not an axiom in its own right). No probabilistic failure event.

The lift's only realisable probabilistic failure event is the P1 (Groth16) break. The prior triple-bundle decomposition included `tdxAdv` and `hashAdv` summands that did not correspond to load-bearing failure modes:

- `tdxAdv` was a holdover from the over-bundled cycle-6.5 `handshake_sound_negl` decomposition.
- `hashAdv` (collision resistance on `commitHashE`) was a *future* refinement target — a real probabilistic failure for P2 would require replacing `pkOfUserData_commitHash`'s use of `commitHash_inj` with a collision-resistance hypothesis. That refinement is its own cycle (the methodology-v0.2 Ask 3 strengthening; not in scope for cycle 6.6).

Cycle 6.6 corrects the over-bundling: the lift is now single-bundle (Groth16-only), matching the actual axiom consumption *modulo* the classical `commitHashE` and ECIES axioms (which remain consumed in the proof but do not contribute probabilistic failure summands).

## Changes

### Added — content-bearing predicates, reduction, advantage

In `ProtocolVCVioTriple.lean`, after the adversary type definitions and before the `handshake_binds_ecies_key_classical` corollary:

```lean
def handshakeBindsWinPred
    (p : HandshakeCheck × UserDataCommit × PrivKey × Plaintext) : Prop :=
  let (h, c, sk, pt) := p
  Accepted h ∧
  h.msgUserData = commitHash c ∧
  keyOf sk = c.eciesPubkey ∧
  ¬ ( (∃ q, was_signed_by_dstack q ∧ userDataOf q = some h.msgUserData) ∧
      pkOfUserData h.msgUserData = some c.eciesPubkey ∧
      decrypt sk (encrypt c.eciesPubkey pt) = some pt )

def reduce_binds_to_groth (𝒜 : HandshakeBindsAdv) : Groth16SoundAdv :=
  fun n => do let p ← 𝒜 n; pure (p.1.proof, p.1.inputs)

noncomputable def bindsFailAdv (𝒜 : HandshakeBindsAdv) (n : ℕ) : ℝ≥0∞ :=
  Pr[ handshakeBindsWinPred | 𝒜 n ]

theorem handshakeBindsWinPred_imp_groth16SoundnessWinPred_projected
    (p : HandshakeCheck × UserDataCommit × PrivKey × Plaintext)
    (hp : handshakeBindsWinPred p) :
    groth16SoundnessWinPred (p.1.proof, p.1.inputs) := by
  obtain ⟨⟨hZk, hMr, hUd⟩, h_commit, h_sk, h_neg⟩ := hp
  refine ⟨hZk, ?_⟩
  intro h_signed
  apply h_neg
  refine ⟨⟨inputs_to_quote p.1.inputs, h_signed, hUd⟩, ?_, ?_⟩
  · rw [h_commit]; exact pkOfUserData_commitHash p.2.1
  · rw [← h_sk]; exact roundtrip p.2.2.1 p.2.2.2
```

`groth16SoundnessAdv`, `groth16SoundnessWinPred` from cycle 6.4 are imported via the already-opened `ProtocolVCVio` namespace.

### Replaced — the lift theorem itself

Was (12 params, including free `bindsFailAdv`, three free advantage abbrevs, assumed `h_bound`, three independent negligibility hypotheses):

```lean
theorem handshake_binds_ecies_key_negl
    (𝒜 : HandshakeBindsAdv)
    (𝒜_groth : Groth16SoundAdv)
    (𝒜_tdx : TdxVerifierSoundAdv)
    (𝒜_hash : CommitHashCollisionAdv)
    (bindsFailAdv : HandshakeBindsAdv → ℕ → ℝ≥0∞)
    (groth16Adv : Groth16SoundAdvantage)
    (tdxAdv : TdxVerifierSoundAdvantage)
    (hashAdv : CommitHashCollisionAdvantage)
    (h_bound : ∀ n,
      bindsFailAdv 𝒜 n ≤
        groth16Adv 𝒜_groth n + tdxAdv 𝒜_tdx n + hashAdv 𝒜_hash n)
    (h_groth_negl : negligible (groth16Adv 𝒜_groth))
    (h_tdx_negl : negligible (tdxAdv 𝒜_tdx))
    (h_hash_negl : negligible (hashAdv 𝒜_hash)) :
    negligible (bindsFailAdv 𝒜) :=
  negligible_of_le h_bound
    (negligible_add (negligible_add h_groth_negl h_tdx_negl) h_hash_negl)
```

Now (2 params; single-bundle; bound proven):

```lean
theorem handshake_binds_ecies_key_negl
    (𝒜 : HandshakeBindsAdv)
    (h_groth_negl :
      negligible (groth16SoundnessAdv (reduce_binds_to_groth 𝒜))) :
    negligible (bindsFailAdv 𝒜) := by
  refine negligible_of_le ?_ h_groth_negl
  intro n
  show Pr[ handshakeBindsWinPred | 𝒜 n ] ≤
       Pr[ groth16SoundnessWinPred | reduce_binds_to_groth 𝒜 n ]
  rw [show reduce_binds_to_groth 𝒜 n
        = 𝒜 n >>= pure ∘
            (fun p : HandshakeCheck × UserDataCommit × PrivKey × Plaintext =>
              (p.1.proof, p.1.inputs))
        from rfl,
      probEvent_bind_pure_comp]
  exact probEvent_mono (fun p _ hp =>
    handshakeBindsWinPred_imp_groth16SoundnessWinPred_projected p hp)
```

## Axiom closure verification

```
'Specs.Quartz.Protocol.ProtocolVCVioTriple.handshake_binds_ecies_key_negl' depends on axioms:
  [propext, Classical.choice, Quot.sound,
   Addr, DomainSep, Nonce,
   commitHashE,
   MrEnclave, TdxQuote, UserData, tdxVerifier, was_signed_by_dstack,
   Groth16Proof, PublicInputs, VKey, groth16Verifier,
   Plaintext, PrivKey, PubKey, keyOf]
```

What is and is not shadowed:

- **`groth16Verifier.sound` projection**: SHADOWED by `h_groth_negl`. The lift correctly takes the Groth16-soundness implication as a parametric negligibility hypothesis rather than consuming it as a classical-Prop axiom.
- **`commitHashE`**: STILL CONSUMED (not shadowed). The proof uses `pkOfUserData_commitHash`, which projects from `commitHash_inj`, which projects from `commitHashE.injective`. Refining this to a probabilistic collision-resistance hypothesis is a separate cycle (would require replacing `pkOfUserData_commitHash`'s formulation).
- **`tdxVerifier`**: in closure as substrate for `mrEnclaveOf`/`userDataOf` (via projections used in `Accepted`'s definition). `tdxVerifier.sound`/`.complete` are NOT separately consumed.
- **ECIES axioms (`PrivKey`, `PubKey`, `Plaintext`, `keyOf`)**: in closure as carriers. `roundtrip` is a derived theorem (defined from how `encrypt`/`decrypt` operate), not a separately-named axiom, so no soundness-style ECIES axiom appears.

Net: 1 of 3 prior summand bundles correctly shadowed; 2 remain in the classical-axiom closure. This is honest about what cycle 6.6 achieves: it closes the Groth16 surface for this lift but defers the `commitHashE` collision-resistance refinement to a separate cycle.
