## What Round A attack #6 was about

`ProtocolSpec` was defined at `ProtocolVCVio.lean:200-202` as the sum
of the four companion-module `OracleSpec`s, but never actually
consumed: every adversary type was `ℕ → ProbComp T`, i.e.
`ℕ → OracleComp ∅ T` (no oracle access). The spec was structural
scaffolding only and downstream lifts could not distinguish a
query-bounded adversary from a computationally-unbounded one. The
placeholder `IsPPT := True` from cycle 6.12 was therefore the only
honest framing available, because `PolyQueries` (the substantive
PPT predicate) requires an `OracleComp`-valued adversary type.

## Approach

Two-step lift:

1. **Honest deterministic simulator scaffolding** (`ProtocolVCVio.lean`
   lines ~204-322): define `protocolSpecHonestSim : QueryImpl ProtocolSpec ProbComp`
   by combining four per-component honest responders via VCV-io's
   `QueryImpl.add` (`+`). Each responder pures the value of the
   corresponding classical-Prop function: `commitHash uc`,
   `commitHashBytes b`, `verifyTdxQuote q`, `verifyGroth16 vkey p ins`.
2. **Adversary type lift**: change every
   `def XAdv : Type := ℕ → ProbComp T` to
   `def XAdv : Type := ℕ → OracleComp ProtocolSpec T`. Wrap every
   advantage def's `Pr[winPred | 𝒜 n]` as
   `Pr[winPred | simulateQ protocolSpecHonestSim (𝒜 n)]`. Reductions
   between adversary types reuse the `OracleComp` monad structure
   (with explicit type annotations on `do let p ← 𝒜 n` to help the
   elaborator resolve field projections).

## Why "honest deterministic" is the right baseline (not "honest random")

A randomised handler (e.g. VCVio's `randomOracle`) is the right
model when the underlying primitive is a random oracle — e.g.
`commitHash` modelled as a uniform-random function from
`UserDataCommit` to `UserData`. Adopting it requires
`[Fintype UserData]` (and `[Fintype UserDataCommit]` for the
two-sided birthday bound), both blocked on carrier refinement
queued from Steps 2–5.

Until those carriers refine to concrete byte-list / `BitVec n`
representations, the honest-deterministic baseline is the
strongest semantics we can state at the spec layer: it gives the
adversary oracle access *at the type level* (so `IsPPT := PolyQueries`
becomes meaningful in cycle 6.14) without smuggling in unverified
`Fintype` content.

## What the lift theorem proofs look like post-cycle-6.13

The proof skeleton for non-degenerate single-failure-mode lifts
(e.g. `handshake_sound_negl`) is now:

```lean
theorem handshake_sound_negl
    (𝒜 : HandshakeSoundAdv)
    (h_groth_negl :
      negligible (groth16SoundnessAdv (reduce_handshake_to_groth 𝒜))) :
    negligible (handshakeFailAdv 𝒜) := by
  refine negligible_of_le ?_ h_groth_negl
  intro n
  show Pr[ handshakeSoundnessWinPred |
              simulateQ protocolSpecHonestSim (𝒜 n) ] ≤
       Pr[ groth16SoundnessWinPred |
              simulateQ protocolSpecHonestSim
                (reduce_handshake_to_groth 𝒜 n) ]
  rw [show reduce_handshake_to_groth 𝒜 n
        = 𝒜 n >>= pure ∘ (fun h : HandshakeCheck => (h.proof, h.inputs))
        from rfl]
  simp only [← map_eq_bind_pure_comp, simulateQ_map, probEvent_map]
  exact probEvent_mono (fun h _ hp =>
    handshakeSoundnessWinPred_imp_groth16SoundnessWinPred_projected h hp)
```

Three new simp lemmas thread the `simulateQ` through the reduction:

- `← map_eq_bind_pure_comp` rewrites the `bind/pure ∘ f` form (which
  the `rw [show ... from rfl]` produces) into `<$>`/`map` form.
- `simulateQ_map` pushes `simulateQ` past `<$>` because `simulateQ`
  is a `LawfulMonad` morphism.
- `probEvent_map` reduces `Pr[winPred | f <$> mx]` to
  `Pr[winPred ∘ f | mx]`, exposing the form `probEvent_mono` needs.

Degenerate-zero lifts (`session_confidentiality_negl`,
`session_confidentiality_via_extractor_negl`) and the foundational
single-bundle lift (`verifyGroth16_yields_decoded_negl`) keep their
existing proof skeletons unchanged — `probEvent_mono` and
`probEvent_False` operate on the result `ProbComp` regardless of
whether it was obtained via `simulateQ` or directly.

## Honesty caveat: degenerate equivalence for current adversaries

For a no-oracle-access adversary (one whose `OracleComp` body
contains no `ProtocolSpec` queries — only `pure`, `bind`, and
`unifSpec` operations), `simulateQ` is observationally equivalent
to the identity on `ProbComp`. So the cycle-6.13 advantage def
agrees with the pre-cycle-6.13 form for any adversary that does
not query the four protocol oracles.

This is the right design: the upgrade strictly widens the
admissible adversary class (oracle-querying adversaries are now
permitted) but does not change the meaning of the lift for the
already-admissible no-oracle-access class. Existing
`negligible (groth16SoundnessAdv 𝒜)` hypotheses remain valid;
new oracle-querying adversaries can be reasoned about under the
same hypothesis shape.

The substantive cryptographic gain over cycle 6.12 is the type
shape: `PolyQueries` can now be specialised onto `XAdv`
(cycle 6.14), giving the `IsPPT` filter real content for the first
time in the refactor.
